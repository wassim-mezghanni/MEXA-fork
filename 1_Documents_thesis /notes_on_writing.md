# Notes on writing

The elements below can mainly help to write a thesis, but they can also be applied to write an article.

A few points:
- The audience you can aim for is someone with a background in Machine Learning, possibly in Natural Language Processing, but not on your specific topic (e.g., task, model, language).
- Do not hesitate to put illustrations or examples to help the reader navigate your explanations.
- It is better to have balanced chapters in a thesis: the background (what you have read), the methodology (what you have done), and the result (what you obtained) chapters should have more or less equal importance.
- Experimental settings can be named to make it easier for the reader to follow the methodology and the result sections.
- Citations should be included whenever you refer to a work (notably, models and corpora), especially if you haven't mentioned the work in the current section/chapter.
- What usually needs to be covered in the thesis or article: datasets and resources, models, training method (if applicable), evaluation method (metrics).
- If possible, please avoid the following words: important, interesting, and big.

## Abstract
- If your work is specific to some languages (or datasets), you can mention them in the abstract (if not too long).

## Introduction
- Two paragraphs to end the introduction:
  - A paragraph with bullet points to summarise the contributions of the thesis
  - A paragraph detailing the structure of the thesis

## Background / Related works
- This thesis chapter allows you to describe all the concepts needed to understand your topic.
- It should not be a simple list of articles: it should be clear how and why you grouped them in that order, and what you want to explain in this part.
- Any methodological choice (e.g., why we consider this model for the experiments) should be motivated in the later chapters.

## Figures
- Vectorised figures are preferred. You can usually save Python figures in PDF and integrate them into LaTeX.

## Tables
- The booktabs package gives better-looking tables (this is a suggestion).
- When you have a large number of results in tables, you can put the best result(s) in bold font. This highlights the best model or experimental setting when comparing.

## Figures, tables, and equations
- Use the corresponding LaTeX environment when inserting a figure, table, or equation.
They should all have a number (e.g., Figure 2.3, Table 4.3, Equation (2)) and be mentioned in the text you are writing (e.g., in Figure 2.3, in Table 4.3 <- using labels and \ref{}, or in Equation (2) <- using \eqref{}).
- Captions should be clear, more or less on their own.

## Methodology chapter/section
- The motivation behind the model choices should be clear. We need to know why we consider model A and model B?

## Results chapter/section
- To make it easier to read, the experimental setting and motivation can be briefly mentioned (with a reference to the corresponding Methodology section) before presenting the results. One or two sentences for this is enough.
- The results should not be simply a description of the results in the table/figure. The goal is to see whether we see a specific trend, anything expected or not expected, or whether we answer some research questions.

## Reproducibility
- Please report anything needed to reproduce your experiments: mainly the hyperparameter values.

## Miscellaneous
- URL links should be in a \url{} command.

## Conclusion
- The conclusion should mention future work.
- You can also mention the Limitations of your work (with a paragraph in the conclusion of a thesis, with an explicit section in an article)

## References
- If possible, please use the same guidelines as in the ACL articles: https://acl-org.github.io/ACLPUB/formatting.html#paper-format (cf. Citations subsection). The citations should look like (Author et al., year).
- There should be hyperlinks from the main part to the reference section
- When citing an article, the peer-reviewed version should be preferred (to an arXiv version).
E.g., you can use the references from the ACL Anthology (or other conferences or journals)
- Hallucinated references (generated by LLMs) are heavily penalised.

## Appendix
- The appendix material has to be mentioned in the main text.
- However, it should not contain anything crucial to understanding your work.

## Code material
- You must provide the code material: either using a GitHub link or as a ZIP file when submitting the thesis.
- Your repository should have a README file. If possible, you can put the commands to replicate your results.
- To decide whether you should publish a given code, you can ask yourself if it is needed to reproduce your results in the thesis.

## On the usage of AI tools
We follow the ACL policy on that point: https://2023.aclweb.org/blog/ACL-2023-policy/
